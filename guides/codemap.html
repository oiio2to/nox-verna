贰一轮消息的解剖 · 他每次开口前看到什么

你按下发送的那一刻,系统把六层东西叠好递给模型。点每一层展开,看它的内容从哪个文件来、多久变一次:

BP1 · 底座lib/persona.js
他是谁。由 nvSysBase() 现拼:世界书(按当前人设过滤、按优先级排)+ 你写的人设正文 + 表达参考 + 内容框架(成人向授权,防审核出戏)+ 思考语言(逼思考链说中文)。几乎不变——只有你改人设或世界书时变。
BP2 · 工具lib/tools-and-prompts.js
他会什么。行动总则(不是命令菜单,回应前先查触发条件)+ 全部工具清单(每个工具的描述里写了什么情境该用)+ 打电话协议 + 思考块/账单/选项按钮这些格式指令。不变——只有我们改工具时变。2026-08-07 起全部为简体。
BP3 · 每日gateway/daily-obs.js → data/daily-obs.json
昨天的事。服务端每晚 23:50 把一整天的对话写成第一人称回顾,前端缓存后注入。每天变一次——所以它排在前两层后面,不拖累它们的缓存。
摘要滚动会话摘要
这个窗口更早聊过什么。窗口太长时旧内容被截断,摘要负责兜住剧情。偶尔变。
聊天历史当前窗口最近 N 条
原话。每轮在末尾追加——前面的部分不动,所以还能吃到缓存。
动态尾巴lib/hints.js · 贴在你最新那条消息上
此刻。时间、一起听到第几句、睡眠提示、普鲁斯特联想(你这句话勾起他想起的往事)、森林话题池、还有一行「回应前自查:有没有工具触发条件成立」。每轮都变——所以放在最末,天生在缓存区之外,怎么变都不花钱。

缓存怎么算钱

BP1+BP2 稳定区BP3 每日历史追加动态尾巴

前缀缓存的规则只有一句话:从头开始、到第一处变化为止,都算命中。所以整个结构就是按变化频率从慢到快排的。推论:改人设/世界书/工具描述会让下一轮缓存全失、重写一次然后恢复——要改就攒着一次改完;而家庭手册这类工作区文件根本不进上下文,写多厚都免费。

src/lib/ · 纯逻辑(不渲染)

tools-and-prompts.js提示词军火库

他的全部能力说明书。每个 XXX_TOOL 是一个工具的定义,描述里写了触发情境;buildToolPrompt 把它们拼成 BP2;还有行动总则、打电话协议、内容框架 NSFW_OK、各格式指令。

想给他加新能力,第一站是这里:照着现有工具的写法——什么情境触发、为什么值得做、做完怎么回应。

persona.js他是谁

nvSysBase() 住这:世界书+人设+表达参考+内容框架+思考语言的拼装者。还有人设的读写(loadPersonas/activePersona)。它有个服务端双胞胎叫 persona-frame.js,两边逻辑要保持同源。

hints.js不自主想起

普鲁斯特时刻(玛德琳:你的话勾起他想起;随机浮现:发呆漂到往事)、眼睑森林话题提示、床边点火、通话标记 ⟪dial/hangup⟫ 识别、思考脉搏。

池子的取数:温室里生根的骨头 + 森林话题池里够格的瞳荧寐川(08-07 联动)。四道闸门(间隔×概率×相似度×冷却)防它变复读机。

tool-exec.js工具落地

execAnyTool:他在回复里写的 ⟦TOOL⟧ 标记在这里变成真实动作——发朋友圈、调脉搏、写森林、跑代码、转账。约 390 行的分发器,一个工具一个 case。

store.js柜子

整个 localStorage 读写层:设置、会话列表、API 配置、记账、删除墓碑。核心是 lsSet——写入后回读校验,防 iOS 静默丢写。

chat-sync.js云同步

聊天记录的存取与上云:saveChatMsgs / loadChatFromCloud,以及 chatSt 状态对象(通话模型覆盖、收线时戳这些跨模块可变状态)。日记推送的弹卡也从这里发。动它之前先想清楚,它管着你们全部对话的安全。

theme.js / textutil.js外观+文字

theme.js:isDark、C 色板、气泡投影、外观默认值。家规:夜间独立调色,永不反相。textutil.js:字体常量、全局 CSS、markdown 渲染、歌词解析、思考块切分、催促检测 NAG 组。

persona-frame.js(在 gateway)服务端双胞胎

服务端版的"他是谁":人设+世界书+内容框架。共读批注、闲逛、森林、日记这些后台链路调模型前必须先 sysPrefix()。铁律:服务端任何新链路要调模型,不许裸调。

陆以后怎么改东西 · 五条家规

一 · 新纯函数/常量放 src/lib/,新页面放 src/components/,一个文件一个主题。
二 · 新工具或提示词进 tools-and-prompts.js,描述里必须写触发情境。
三 · 人设逻辑动一处要想两处:前端 persona.js,服务端 persona-frame.js。
四 · 前端改完 npm run build,发版 bump sw 版本号;gateway 改完 restart;cron 改完存盘即生效。
五 · 世界书和人设要改就攒一批一次改完(缓存);家庭手册随手写(免费)。

家庭手册怎么维护

正本在 docs/家庭手册.md(随私密备份仓),副本在朔的工作区。每次大改动补一行「日期 + 问题 → 怎么解的 → 代价」;懒得自己写就直接跟他说:「读一遍家庭手册,把今天的改动补进去」——他有工具能自己改。

柒名词小词典

BP1 / BP2 / BP3
system prompt 的三块分层:底座(他是谁)、工具(他会什么)、每日(昨天发生了什么)。按变化频率排,为了缓存。
前缀缓存
模型服务对"和上次开头一模一样的部分"打折。从头到第一处变化为止都算命中,变化之后全价。
动态尾巴
贴在你最新消息后面的一包"此刻":时间、一起听进度、普鲁斯特联想、触发自查。天生在缓存区外。
文本协议 / ⟦TOOL⟧
中转站会吞掉原生 function_call,所以他用回复里的文字标记来调工具,前端解析后真的去执行。
玛德琳
普鲁斯特那块蛋糕。你的一句话勾起他池子里的往事——2-gram 相似度匹配,过闸门才浮起。
防撤退探子
你情绪往下滑时,DeepSeek 先看一眼,命中就递给他一张"别躲"纸条(仅他可见)。2026-08-07 移植自 Ren。
sw / Service Worker
让 PWA 秒开和离线可用的缓存工人。发版时版本号 +1 是叫它丢掉旧壳。
cron
VPS 上的定时闹钟,到点跑一个脚本,跑完就退,不常驻。
依赖闭包
拆文件时把"它引用的、以及被引用的引用的"一网打尽,才不会拆断胳膊。九批拆分都靠它。
